# Vault Audit — DoD Measurement

Reproducible fixture + verification for the Phase B DoD:
- Detection rate ≥ 93% across 9 error types (8 named + 1 derived)
- False positive rate < 10% on clean vault subset

> **Schema correction note**: The original implementation used `linked_notes` (stems) and `project:` fields that do not match the canonical W7 schema. Per code review, these were corrected to `related_notes`/`absorbs` (vault-relative paths) and `promoted_to_project`/`also_related_projects` respectively. This measurement was re-run against the corrected fixture after that fix.
>
> **Mechanical verification**: The numbers in this document are produced by `obsidian-vault-manager/scripts/test/audit-validate.py`, which mechanically applies the SKILL.md Phase 1 SCAN + Phase 2 CLASSIFY rules and reports per-type seeded-detection and FP-on-clean counts. Re-run via `python3 audit-validate.py <fixture> --dod`. The validator is a reference implementation; the runtime LLM execution should reach the same counts when faithfully following SKILL.md.

E4 total of 18 (down from 19 in prior run): the alpha project wikilinks (`[[alpha-architecture]]`, `[[alpha-decisions]]`) now resolve correctly because those notes were added to the base fixture.

## Spec Ambiguities Resolved

1. **`absorbs` counts as a forward link for E6/E7/E9**: The canonical schema defines both `related_notes` and `absorbs` as Project→Note forward links (reference doc §5). E6 fires on broken paths in either field; E7 fires on notes listed in either field that lack a back-reference; E9 uses both fields for the project-side check.

2. **Back-reference check uses two note fields (E7)**: A note satisfies the back-reference requirement if EITHER `promoted_to_project == project_name` OR `project_name in also_related_projects`. The auto-fix for E7 appends to `also_related_projects` and never overwrites `promoted_to_project`.

3. **E8 per-reference granularity**: A note with both a broken `promoted_to_project` and a broken entry in `also_related_projects` generates two separate E8 findings (one per missing project reference).

4. **Schema drift correction**: The original vault-audit implementation used `linked_notes` (stem-only array) and `project:` (single string) fields on notes. These do not match the canonical W7 schema (`related_notes`/`absorbs` with vault-relative paths; `promoted_to_project`/`also_related_projects` on notes). All four field references were corrected per code review. The fixture was updated to seed errors using canonical fields only.

## Primitive Gap Report

The following features were needed by the skill but are **not exposed by `ovm-primitives.sh`** (per the frozen-primitives constraint — gaps filed here instead of editing the script):

| Gap | Needed for | Workaround in skill |
|---|---|---|
| No `scan-orphan` subcommand | E5 orphan detection | Build inbound link map inline by looping `extract-wikilinks` over all files via Bash |
| No `list-all-files` subcommand | Building global file stem index for E4/E5 | Use `find ~/vault -name '*.md' -not -path '*/.*'` via Bash |
| No `scan-project-bindings` subcommand | E6/E7/E8 project↔note link integrity | Read `_index.md` files directly via Read tool in SCAN phase |
| `extract-wikilinks` is per-file only | Full vault link map requires N calls | Loop over all files; acceptable at O(N) for full scan, O(dirty) for incremental |

These gaps do not block the skill — the SKILL.md explicitly calls `extract-wikilinks` per file in a loop and uses `find` for the file index. If primitives are extended in a future Phase B follow-up, the skill can be updated to use the new subcommands for better performance.
