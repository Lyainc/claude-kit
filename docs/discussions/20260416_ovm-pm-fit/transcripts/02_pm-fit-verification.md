# Transcript 02 — PM 1-4가 OVM에 정말 부합하는가

**[Moderator]**: 재정의된 OVM에 PM 1-4가 "부록"인지 "중심"인지 검증.

**[Knowledge Management Expert]**: PARA 관점. Projects는 "active goals with deadlines" — 포트폴리오 관리는 PARA **핵심 운영**. OVM이 PARA를 지원한다면 PM은 **중심 기능**.

**[Product Strategy Expert]**: 동의. "vault 관리자"가 개별 생성만 지원하고 프로젝트 간 의존성·아카이브 판단을 못하면 상품 불완전. 100개 note 후 "이제 뭐?" 답이 없음.

**[Critical Practitioner]**: inbox-review는 "한 inbox 파일들" 범위. PM은 "전체 vault 포트폴리오" — 수십 배 넓다.

**[Plugin Architecture]**: 넓이가 scope creep의 정의가 아니다. **동종성**이 기준. PM은 inbox-review·context·archive와 동종(메타·배치·vault-내부), 상위 granularity일 뿐.

**[Optimistic]**: 구체 스킬로 검증. `/plan-audit` = inbox-review의 포트폴리오 버전. `/plan-consolidate` = note의 메타 버전. 기존 패턴과 **구조적 유사**.

**[PM]**: PARA 실천자 주간 리뷰에서 포트폴리오 정비는 note 생성만큼 빈번. 이걸 지원 안 하면 실무 공백.

**[Critical]**: 방향 합의 가능. 단 implementation 경계 엄격 — OMC planner 위임, vault 내부만 쓰기, orchestration 제외.

**[Moderator]**: 합의안 — PM 1-4는 OVM의 PARA 완성 위한 핵심. 경계 3종으로 scope 오염 방지.

**전원 합의.**

**결론**: PM 1-4는 OVM 본연의 임무.
