## 각 행이 답해야 하는 질문

| 행 | 의미와 유지할 내용 |
|---|---|
| NEXT | 이번에 제안하는 하나의 응집된 작업은 무엇인가? |
| FROM + 대상 | 출처와 선택 요구는 무엇인가? Seed 소속을 한 번 쓰고 각 ID의 기존 요약 설명을 남겨요. |
| 근거 | 어떤 관측된 미충족 때문에 필요한가? |
| 착수 | 지금 시작할 수 있는 이유 또는 미확인 조건은 무엇인가? |
| 변화 | 끝나면 사용자가 무엇을 다르게 할 수 있는가? |
| SKIPPED | 다른 후보는 왜 보류·제외됐는가? |
| TRACE | 어디까지 탐색했고 어떤 근거·경고·실패가 있는가? |

ID 범위만 남기면 선택 요구의 뜻이 사라져요. 그래서 3개 이상일 때 설명을 없애던 분기를
삭제하고, 출처가 분명한 문맥에서 반복 소속만 줄여요. 기존 첫 문장·80자 설명 제한은
그대로예요. 설명 전체를 무제한으로 출력하거나 원래 제한까지 없앤 것은 아니에요.

## #862 안전 확인과 축약의 분리

- **Source safety:** 전문·포인터 모두 현재 자격/버전과 기준 가용성을 확인하고 변경·미확인은
  적용을 보류해요. 통과 후 원문·기준 이후 변경을 대화에 올려요. 목표에는 짧은 시작 조건을
  한 번 쓰고 metadata/diff/read 절차를 거듭 풀어 쓰지 않도록 했어요.
- **Abbreviation:** 검증된 원본으로 복원되는 배경·요구 재서술만 선택적으로 대체해요.
  원본/pin이 없으면 전문이에요. 길이를 줄이려고 원본이나 SHA를 만들지 않아요.
- 호출자의 모든 검사·옵션·채점 주의·보호·실제 Git 권한·미확정 사실·리뷰/base/상한은 남겨요.
  '검사 하나만'으로 대체하지 않아요. 호출자가 검사를 지정하지 않아도 검증된 관련 검사와
  exit 0을 요구하며, 명령이 미확인이면 완료를 주장하지 않아요.
- local-harness 호출자는 배치만 소유하고 목표를 다시 축약하거나 권한을 늘리지 않아요.
