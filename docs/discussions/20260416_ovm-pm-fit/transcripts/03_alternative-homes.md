# Transcript 03 — OVM 외 대안 후보 재심

**[Moderator]**: 마지막 점검. OVM 이외 더 자연스러운 홈이 있나.

**[Plugin Architecture Expert]**: 후보별 평가 —
- **vault-bridge**: I/O 서빙, haiku-tier. PM은 opus-tier 분석. **티어 불일치**. 또 "서빙"은 요청-응답, 의사결정 아님.
- **thinking-tools**: 분석 도메인 일치. 하지만 PM artifact는 vault 경로 저장 필요. thinking-tools는 vault 쓰기 패턴 부재.
- **신규 플러그인**: 이전 패널 C 선택했으나 TOPIC 2에서 OVM 부합 판정. 재철회.

**[Knowledge Management Expert]**: vault-bridge는 "외부↔vault 통로". PM은 "vault 내부 상태 분석". 방향 어긋남.

**[Product Strategy Expert]**: 사용자 멘털 모델 — "vault 관련 명령은 뭐에?" → OVM 먼저. 자연스러움.

**[Critical Practitioner]**: 이름 부합도. `obsidian-vault-manager`. PM은 vault를 "관리"하는 활동. OVM 압승.

**[Optimistic]**: vault-bridge에 `/plan-audit` 있으면 사용자 "I/O 플러그인 기능?" 혼동. 이름에서 패배.

**[PM]**: 이의 없음.

**[Moderator]**: 정리 — OVM이 유일하게 부합. 대안 모두 열위.

**전원 합의.**

**결론**: OVM 홈 최종 확정.
